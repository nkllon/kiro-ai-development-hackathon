# Vocabulary by Implementation Phase

**Projection Dimension:** Implementation phase organization
**Purpose:** Organize terms by when they're needed in implementation

## Foundation Phase

**Relevant Categories:** Core Framework, Reflective Architecture
**10 terms** needed in this phase

### Ad-hoc Approach
*Core Framework - The approach Beast Mode systematically replaces*

Unstructured development methodology that relies on guesswork, workarounds, and reactive problem-solving without systematic planning or measurement.

**Related:** Workaround, Guesswork, Reactive Development

---

### Beast Mode Framework
*Core Framework - The foundational systematic approach to development*

A systematic development engine that transforms regular hackathons into structured domination through PDCA cycles, tool health management, and model-driven decision making.

**Related:** PDCA Orchestrator, Tool Health Manager, Project Registry

---

### Capability Discovery
*Reflective Architecture - Dynamic capability management*

Process by which modules automatically discover and register their capabilities at runtime.

**Related:** ReflectiveModule, ModuleCapability, Runtime Adaptation

---

### Fix Tools First
*Core Framework - Primary principle of Beast Mode methodology*

Core principle of repairing actual problems systematically rather than implementing workarounds.

**Related:** Systematic Repair, Root Cause Analysis, Tool Health

---

### Model-Driven Intelligence
*Core Framework - Decision making approach in Beast Mode*

Using project registry data and domain knowledge instead of guesswork for decision making.

**Related:** Project Registry, Domain Knowledge, Intelligence Engine

---

### ModuleCapability
*Reflective Architecture - Module capability definition*

Enumeration of capabilities that a module can provide, enabling dynamic capability discovery.

**Related:** ReflectiveModule, Capability Discovery, Module Interface

---

### ModuleHealth
*Reflective Architecture - Module health monitoring*

Health status of a module including healthy, degraded, unhealthy, and unknown states.

**Related:** HealthStatus, ModuleStatus, Health Monitoring

---

### ModuleStatus
*Reflective Architecture - Module operational status*

Operational status of a module including healthy, warning, error, and unknown states.

**Related:** ModuleHealth, Status Monitoring, Module State

---

### ReflectiveModule
*Reflective Architecture - Core architectural pattern*

Base class for all modules that can discover their own capabilities, monitor their health, and adapt at runtime.

**Related:** ModuleCapability, ModuleHealth, ModuleStatus

---

### Systematic Superiority
*Core Framework - The primary goal of Beast Mode methodology*

Demonstrable performance advantages over ad-hoc approaches through measurable metrics and systematic validation.

**Related:** Ad-hoc Approach, Metrics Collection, Comparative Analysis

---

## Design Phase

**Relevant Categories:** Domain-Driven Design, Quality Assurance
**11 terms** needed in this phase

### AggregateRoot
*Domain-Driven Design - Tactical design pattern*

An entity that controls access to a set of related objects and ensures consistency within the aggregate boundary.

**Related:** Entity, Value Object, Domain Event

---

### BoundedContext
*Domain-Driven Design - Strategic design pattern*

A boundary within which a particular domain model is defined and applicable.

**Related:** Domain Model, Ubiquitous Language, Context Map

---

### Compliance
*Quality Assurance - Standards adherence*

Adherence to established standards, rules, or requirements.

**Related:** Standards, Requirements, Adherence

---

### DomainEvent
*Domain-Driven Design - Event-driven architecture*

An event that represents something significant that happened in the domain.

**Related:** AggregateRoot, Event Sourcing, Domain Service

---

### DomainService
*Domain-Driven Design - Domain logic organization*

A service that represents a domain concept that doesn't naturally fit as an entity or value object.

**Related:** Domain Model, Business Logic, Stateless Service

---

### Entity
*Domain-Driven Design - Tactical design pattern*

An object that has a distinct identity that runs through time and different states.

**Related:** ValueObject, AggregateRoot, Identity

---

### Metrics
*Quality Assurance - Performance measurement*

Quantifiable measures used to track and assess performance, quality, or progress.

**Related:** Measurement, Performance, Assessment

---

### Quality Gate
*Quality Assurance - Quality control mechanism*

A checkpoint in the development process where quality criteria must be met before proceeding.

**Related:** Quality Criteria, Validation, Checkpoint

---

### Ubiquitous Language
*Domain-Driven Design - Team communication and modeling*

A common language used by all team members to connect all activities of the team with the software.

**Related:** Domain Expert, BoundedContext, Domain Model

---

### Validation
*Quality Assurance - Quality assurance process*

Process of checking that something meets specified requirements and quality standards.

**Related:** Quality Gate, Requirements, Verification

---

### ValueObject
*Domain-Driven Design - Tactical design pattern*

An object that is defined by its attributes rather than its identity and is immutable.

**Related:** Entity, AggregateRoot, Immutability

---
