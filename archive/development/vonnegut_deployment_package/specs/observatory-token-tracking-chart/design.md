# Design Document

## Overview

This design implements the LLM Token Tracking chart as the second functional Chart.js visualization in the Observatory dashboard. The implementation leverages the successful HealthChartInitializer pattern while maintaining complete brownfield safety for the live system.

The design focuses on real token consumption metrics (input, output, total) rather than unreliable cost estimates, providing accurate resource monitoring for LLM API usage across the Beast Mode system.

## Architecture

### High-Level Flow

```
Dashboard Load → Token Chart Init → Data Request → Multi-Metric Rendering → Real-time Updates
     ↓                ↓                 ↓                    ↓                    ↓
HTML Container → TokenChartInitializer → API Call → Input/Output/Total Lines → WebSocket/Polling
```

### Component Integration

The token chart integrates with existing Observatory infrastructure:

```
TokenChartInitializer
    ↓
Direct API Call → /api/dashboard/all-data
    ↓
Data Extraction → apiData.costs (token metrics)
    ↓
Chart.js Rendering → costTrackingChart canvas
    ↓
Real-time Updates → 5-second refresh cycle
```

## Components and Interfaces

### 1. TokenChartInitializer (New Component)

**Purpose**: Safely initialize the token tracking chart without breaking existing functionality

**Interface**:
```javascript
class TokenChartInitializer {
    constructor(canvasId)
    async initialize()
    createChartConfig()
    updateChartWithData(apiData)
    handleInitializationError(error)
}
```

**Responsibilities**:
- Create Chart.js instance for token consumption visualization
- Handle three-metric display (input, output, total tokens)
- Handle initialization failures gracefully
- Maintain brownfield safety with try-catch isolation

### 3. Integration Points

**Data Source**:
- Endpoint: `/api/dashboard/all-data` (same as health chart)
- Data path: `response.costs` section
- Token metrics: Extract from cost tracking data structure
- **CRITICAL**: Need windowing functions to get historical data (10-minute moving window) instead of starting from browser initialization time

**Error Handling**:
- Use established brownfield safety patterns from health chart
- Isolate token chart errors from dashboard functionality
- Graceful degradation to "Loading..." message

**Update Cycle**:
- 5-second refresh interval (matches health chart)
- 50 data point limit for performance
- Automatic scrolling for real-time display
- **WINDOWING REQUIREMENT**: Initial load should fetch 10-minute historical window, then append new data points

## Error Handling

### Brownfield Safety Strategy

**Level 1 - Initialization Protection**:
```javascript
try {
    const tokenChart = new TokenChartInitializer('costTrackingChart');
    await tokenChart.initialize();
} catch (error) {
    console.warn('Token chart initialization failed:', error);
    // Dashboard continues normally, chart shows "Loading..."
}
```

**Level 2 - Runtime Protection**:
```javascript
// All chart operations wrapped in try-catch
try {
    this.updateChartWithData(apiData);
} catch (error) {
    console.warn('Token chart update failed:', error);
    // Show fallback message, don't break dashboard
}
```

**Level 3 - Graceful Degradation**:
- Chart.js load failure → Display text-based token counts
- API failure → Show "Connection lost" with retry button
- Data parsing error → Show "Invalid token data" with diagnostic info

### Error Isolation

**JavaScript Error Containment**:
- All token chart code in isolated try-catch blocks
- No errors propagate to global scope
- Existing Observatory features remain unaffected
- Health chart continues working independently

**Resource Conflict Prevention**:
- No modification of existing canvas elements
- No interference with health chart or emoji rain
- No changes to existing WebSocket handlers
- Separate initialization from health chart

### Test Scenarios

**Happy Path**:
- Dashboard loads → Token chart displays with real data
- LLM calls made → Chart updates with token consumption
- Data available → Chart shows input/output/total trends

**Error Scenarios**:
- Chart.js fails to load → Fallback to text display
- API returns invalid token data → Show "No token data available"
- WebSocket disconnects → Fall back to HTTP polling
- Chart initialization fails → Dashboard continues normally

**Edge Cases**:
- No historical token data → Start with current data point
- Token counts outside expected range → Scale appropriately
- Rapid LLM usage → Debouncing prevents excessive renders
- Browser compatibility → Graceful degradation for older browsers
